# Implementation Plan: Podcast Website

**Branch**: `001-podcast-website` | **Date**: 2026-11-12 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-podcast-website/spec.md`

## Summary

Build a modern, distinctive, responsive podcast website with a landing page featuring one episode, a 20-episode catalog, an about page, and an FAQ. Use Next.js configured for static export. Keep the fictional show copy and episode records embedded in local project content; no database, live feed, playback, API, or server runtime is needed.

## Technical Context

**Language/Version**: TypeScript; use the supported stable version available when initializing the project

**Primary Dependencies**: Next.js App Router, React; Playwright for browser-level verification

**Storage**: No database; episode, show, and FAQ content are local source files

**Testing**: Next.js production build/export, focused content invariants, and Playwright end-to-end checks

**Target Platform**: Static hosting; current desktop and mobile browsers

**Project Type**: Single web application

**Performance Goals**: Static pages load without application-server requests; primary content remains readable and usable at the specified mobile and desktop viewport sizes

**Constraints**: Next.js static export; no server-dependent routes, database, external feed, audio playback, API, secrets, or required third-party runtime service. Use local assets and avoid image optimization that requires a Next.js server.

**Scale/Scope**: Four routes; exactly 20 distinct mock episodes; one featured episode selected from those 20; informational episode cards; expandable FAQ items

## Constitution Check

- **Static Delivery**: PASS. The app will build to static files and require no persistent application server.
- **Accessible, Responsive Experience**: PASS. Pages use semantic markup, keyboard-operable controls, visible focus, and responsive layouts for mobile and desktop.
- **Safe, Simple Client**: PASS. All content is fictional and local; no credentials, database, external data collection, or unnecessary runtime dependency is planned.
- **Delivery Workflow**: PASS. Verify the production build and test affected user flows at mobile and desktop sizes.
